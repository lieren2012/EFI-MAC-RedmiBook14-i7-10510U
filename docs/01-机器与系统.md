## 磁盘分区现状（1TB，GPT）

```
disk0 (1.0 TB)
├─ s1  EFI                   314.6 MB   ← OpenCore 在这，重装系统不影响
├─ s2  Microsoft Reserved     16.8 MB
├─ s3  NTFS  "系统"           85.9 GB   ← Windows 系统盘
├─ s4  NTFS  "软件"          214.8 GB   ← Windows 数据盘（macOS 下只读）
├─ s5  ExFAT "Untitled"      615.3 GB   ← 空的，可用作临时备份盘（macOS 可读写）
└─ s6  APFS Container        108.0 GB   ← macOS 系统（disk1）
      └─ disk1s1 "hgws14.5"  已用 12.6 GB，空闲 46.9 GB
```

## 为什么「扩容」扩不了（已实锤，不是没找对命令）

- APFS 容器 `disk1` 的物理存储只有 `disk0s6` 一个，且它**位于磁盘最末尾**，尾部只剩 20KB。
- `diskutil apfs resizeContainer disk1 0` 报的实际上限就是 `108.0 GB` —— 因为 APFS 只能往**紧邻其后**的空闲空间生长，而 s6 后面什么都没有。
- 前面 615GB 的空 ExFAT（s5）跟 s6 **不相邻**，中间隔着格式，无法直接并进去。
- macOS 没有「把分区往前挪」的能力（没有类似 GParted 的 move 操作）。**唯一办法是删掉 s5 + s6，重建一个跨越两者的 APFS 容器**。

### 结论：只能重装（或迁移），不能无损扩容

好消息是**代价很低**：macOS 系统卷实际只用了 12.6 GB，用户数据按此前扫描约 5.7 GB。具体方案见 `04-重装与恢复.md`。

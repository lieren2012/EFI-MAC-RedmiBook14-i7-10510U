# 03 · 修复记录与根因

> 全部结论均来自实测：`ioreg`、音频电平实测、ACPI 反编译、统一日志（提权导出）。凡没验证过的都标注了「推测」。

---

## 1. 蓝牙（最后修好，也是最绕的）

**现象**：控制器是个空壳 —— `Address NULL / State Off / Chipset BCM_4350C2 / FW v0`，USB 里根本看不到蓝牙设备（本机 `8087:0AAA`），蓝牙开关打不开。

**排查过程**
1. kext 齐全（IntelBluetoothFirmware/Injector/BTPatcher + BlueToolFixup）、personalities 里也覆盖了 `8087:0AAA` → 不是驱动缺
2. 发现 ACPI 加载报错：`ACPI Exception: AE_ALREADY_EXISTS / [_UPC] Namespace lookup failure / (SSDT: _USB)`，`3 table load failures` → **SSDT-USB 整表被丢弃**
3. 原因是改名补丁 `Find = 5f 55 50 43 08` 匹配不上 DSDT 实际写法（标志位不是 0x08），所以 `_UPC` 从来没被改名

**根因（两条，缺一不可）**
- USB 端口映射根本没生效 → 蓝牙所在的内部口是关闭状态
- `IntelBTPatcher` 二进制里的 KernelVersion 上限停在 Sequoia，macOS 26 上直接不加载（[OpenIntelWireless#505](https://github.com/OpenIntelWireless/IntelBluetoothFirmware/issues/505)）

**解法**
- 改名补丁改成 4 字节 `_UPC → XUPC`（不限标志位），另加一条针对 `TableSignature=SSDT + OemTableId=XMCC1901` 的同类补丁
- 换成 **Tahoe 重编的 2.5.3**（`lshbluesky/IntelBluetoothFirmware` 2026-11-03 构建）
- `SSDT-USB.aml` 重写为 14 端口全开：`HS01–HS10 + USR1/USR2 + SS01/SS02`，蓝牙候选口标 `255 (internal)`

**验证**：`Address AA:BB:CC:DD:EE:FF / State On / Transport USB / 固件 v256`，能搜到 iPhone。注意 `ioreg | grep 8087` 查不到属正常（蓝牙不在 USR 口上）。

## 3. 音频 · 扬声器

**现象**：音量条能动，但完全没声音。

**根因**：EFI 里的 `AppleALC.kext` 只有 **87 KB**（正常 1.9.8 是 3.7 MB，资源打包在二进制里），`strings` 搜不到任何 `ALCxxx` → **资源被剥离的残废版**，任何 layout 都回落成 7。

**解法**：换完整 **AppleALC 1.9.8** + `layout-id = 56`（Dell 系，扬声器通路正确）。

**验证**：`SPEAKER_OK`。

## 4. 音频 · 麦克风（最曲折的一条）

**现象**：设备枚举正常、权限正常、音量 100%，但采集电平恒为 0。

**layout 试错链（都是实测，不是猜）**

| layout | 来源 | 结果 |
|---|---|---|
| 69 | 小米 Pro Enhanced 2019（原配置） | 走 0x12 数字麦，不通 |
| 56 | Dell 系 | 扬声器 ✅ / 麦克风 ❌（没有 0x19 麦路径） |
| 99 | Hoping XiaoMiPro 2020 | 48k 新路径，电平仍全零 |
| **21** | **Andres Dell 5570（社区经验来自 MateBook 13/14 项目，但本机 ALC256 实测可用）** | **麦克风 peak 0.49，扬声器正常** ✅ |

**为什么是 21**：ALC256 的麦克风通路是 `0x09 → 0x22 → 0x19 (Boost 3)`，与 56/99 的 `0x08 → 0x23` 完全不同。这也解释了为什么"换个 layout 突然就好了"。

### 4.1 更深的坑：麦克风会被「系统设置 → 声音」面板占用

**现象**：上午还好好的，用一会儿突然没电平，重启才行。

**取证**
```
ioreg -r -c AppleHDAEngineInput
  IOAudioEngineState = 1
  IOAudioEngineNumActiveUserClients = 1     ← 输入引擎永远"在跑"
ioreg -r -c AppleHDAEngineOutput
  IOAudioEngineState = 0
  IOAudioEngineNumActiveUserClients = 0     ← 输出引擎正常空闲
```

**谁占的**：新增 `audio-fix/tools/audioprocs.m`（枚举 `kAudioHardwarePropertyProcessObjectList`），直接点名：

```
pid=2614  Sound  input=YES
→ /System/Library/ExtensionKit/Extensions/Sound.appex
```

**就是「系统设置 → 声音」那一页**。它为了画输入电平表会常驻占用内置麦克风的输入流，导致输入引擎始终 running；此时任何 App 再开录音，拿到的都是已经跑偏的 DMA 环 → 采出来全是 0。

**这解释了整段历史**：你每次"去系统设置看看有没有电平"，这一看本身就把麦克风占了；之后微信语音、WorkBuddy 语音输入全部失灵；USB 麦克风不受影响（独立 USB 音频栈）。

**当前状态**：kill 掉面板后引擎会归零，但 codec 已经进入坏状态，**仍然只有重启能恢复**（重启 coreaudiod、切输入源、切默认设备都试过，全部无效）。

**日常铁律**
- 不要开着「系统设置 → 声音」面板干活，尤其别一边开着它一边录音/语音通话
- 不要两个 App 同时录音
- 不要在设置里来回切采样率
- 看电平用 `bash audio-fix/miccheck.sh`，不要用系统设置

## 5. 触摸板（根因最漂亮的一条）

**现象**：`VoodooI2CDeviceNub` 有实例（`I2C0` 下 `XTPD`，ELAN2303，0x15），但 `VoodooI2CHIDDevice` 实例数 = 0 → 完全无输入。

**为什么以前怎么改都没用**
- 假设备 `XTPD` 挂在 **I2C0**、型号 **ELAN2303** —— 总线编号和型号**全错**，probe 必然失败
- 中途还试过把 `HID2`（描述符地址）从 `One` 改成 `0x0020`，方向对但治标不治本

**怎么拿到真相**
`acpidump` 在 macOS 不可用 → 换成 **OpenCore DEBUG 版 + `Misc/Debug/SysReport = True`**，把 30 张 ACPI 表倒到 `EFI/SysReport/ACPI/`，反编译 249KB 的 `DSDT.aml` + OEM `SSDT-2`：

```
\_SB.PCI0.I2C1.TPD0 : Device
  _HID = ELAN2304
  _CID = PNP0C50
  I2C 地址 = 0x15，GPIO pin 0
```

**根因**：原生设备一直存在，只是 `_STA` 有**三重门**：

| 条件 | macOS 下的值 | 结果 |
|---|---|---|
| `I2CD == 1` | 1 | ✅ 已满足 |
| `OSYS >= 0x07DD` | BIOS 给的不够 | ❌ 挡住 |
| `TPMD == 1` | 0（CNVS 共享内存 0x99ACD018+0x402） | ❌ 挡住 |
| `\SB.TPTP() == 2` | Windows 下能用说明硬件是 2 | ✅ |

**解法**：`SSDT-TPDX.aml`（只有 110 字节）

```asl
DefinitionBlock ("", "SSDT", 2, "HACK", "TPDX1", 0)
{
    External (_SB_.PCI0.I2C1.TPD0, DeviceObj)
    Scope (\_SB.PCI0.I2C1.TPD0)
    {
        If (_OSI ("Darwin"))
        {
            Name (OSYS, 0x07DF)
            Name (TPMD, One)
        }
    }
}
```

作用域内的 `Name` 覆盖同名对象，于是原生 `_STA` / `_CRS` / `_DSM` 全部以 Windows 模式求值，返回 `SBFE`(I2C1 0x15) + `SBFG`(GPIO pin0)。同时**禁用**假设备 `SSDT-TPD0.aml`。

**验证**：`ioreg -c VoodooI2CHIDDevice` 有实例，触摸板可动、手势正常。

## 6. USB 端口映射

`SSDT-USB.aml`（977 字节，自建）：`HS01–HS10 + USR1/USR2 + SS01/SS02`，共 14 口。前身是被 `_UPC` 撞名整表丢弃的版本（见第 1 节）。`UsbConnector` 实测 3/3/0/255/255/3/3，与设定逐一吻合。
